## 3. Постановка задачі

Для варіанта 4 використовується предметна область **«Склад автозапчастин»**.

Формат одного запису:

```text
sku:String; name:String; stock:int; unitPrice:double; supplier:String
```

У вхідному CSV типи полів не записуються; поля розділяються крапкою з комою `;`.

Показники:

1. кількість коректних записів;
2. загальна кількість;
3. вартість запасу;
4. найдорожча деталь.

Програма читає `data/input.csv` або шлях, переданий через `--input`. Для кожного рядка виконується послідовність: прочитати → перевірити → перетворити → включити в обчислення. Некоректний рядок не зупиняє всю програму, а повідомляється його номер і причина пропуску.

До обов'язкових перевірок належать порожній рядок, неправильна кількість полів, порожнє обов'язкове текстове поле, нечислове значення та від'ємні числові значення.

### Виправлені помилки

Під час виконання роботи було виправлено кілька технічних проблем:

1. JAR не мав `mainClass` у manifest — виправлено конфігурацію Maven Shade Plugin.
2. Maven використовував застарілий JUnit 3 — залежність і тест переписано на JUnit 5.
3. Код компілювався під Java 8 — у `pom.xml` встановлено `release 21`.
4. Java 21-клас запускався Java 17 — середовище запуску потрібно узгоджувати з Java 21.
5. SpotBugs виявив можливе розіменування `null` — результат `output.getParent()` збережено в локальну змінну перед перевіркою.
6. GitHub Actions не знаходив `mvnw`, оскільки Maven-проєкт розташований у `LAB_01/lab01` — у workflow враховано робочу директорію проєкту.

Усі рекомендації перед використанням перевірялися через локальні `test`, `verify`, `package` та запуск JAR.

## 8. Відповіді на контрольні питання

### 1. Яке призначення файла `pom.xml`?

`pom.xml` описує Maven-проєкт: його координати, версію Java, залежності та плагіни. За цим файлом Maven знає, як компілювати, тестувати, перевіряти та пакувати проєкт.

### 2. Чим відрізняються `test`, `verify` і `package`?

`test` компілює програму та запускає тести. `verify` виконує попередні етапи і додаткові перевірки, зокрема SpotBugs. `package` виконує попередні етапи й формує JAR у `target/`.

### 3. Навіщо потрібен Maven Wrapper?

Wrapper дозволяє запускати проєкт із визначеною версією Maven без вимоги окремо встановлювати Maven на кожному комп'ютері.

### 4. Яку роль відіграє метод `main`?

`main` є точкою входу консольної Java-програми. Саме з нього починається виконання програми.

### 5. Чим примітивний тип відрізняється від `String`?

Примітивні типи зберігають прості значення, наприклад `int` або `double`. `String` є посилальним типом і використовується для роботи з текстом.

### 6. Чому середнє потрібно обчислювати в `double`, якщо сума і кількість мають тип `int`?

Щоб не виконувати цілочислове ділення. Приведення суми до `double` зберігає дробову частину результату.

### 7. Що станеться, якщо `Integer.parseInt` отримати рядок `"abc"`?

Метод не зможе перетворити текст у число і викине `NumberFormatException`.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач повинен знати, які дані були відкинуті та чому. Тому програма повідомляє номер рядка і причину помилки.

### 9. Як `String.split(";", -1)` обробляє порожнє останнє поле?

Аргумент `-1` змушує `split` зберігати порожні поля в кінці рядка. Завдяки цьому можна правильно виявити відсутнє останнє значення.

### 10. Чому краще використовувати `Path.of`, а не рядок із `/` або `\\`?

`Path` сам використовує платформозалежний роздільник шляхів, тому той самий код працює на Windows, macOS та Ubuntu.

### 11. Навіщо явно задавати `StandardCharsets.UTF_8`?

Щоб кодування файлів не залежало від системних налаштувань і українські символи однаково читалися та записувалися на різних ОС.

### 12. Чим `%n` відрізняється від `\\n` у форматованому виводі?

`%n` вставляє роздільник рядка, прийнятний для поточної ОС. `\\n` завжди означає символ нового рядка LF.

### 13. Які дані потрібно перевірити у вашому варіанті?

Для варіанта 4 треба перевіряти наявність `sku`, `name` та `supplier`, правильну кількість п'яти полів, числовий формат `stock` та `unitPrice`, а також недопустимі від'ємні значення.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібен тест із кількома записами, де правильний результат містить дробову частину. Для інших показників за цим самим принципом використовуються набори з відомим очікуваним результатом.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор перевіряє код або скомпільований байт-код на потенційні проблеми, які можуть не проявитися під час звичайного виконання тестів.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматично запускає збірку та перевірки після змін у репозиторії. У цій роботі він використовується для перевірки на трьох ОС.

### 17. Що має містити GitHub Issue на дефект?

Опис проблеми, кроки відтворення, очікуваний результат і фактичний результат. Виправлення має бути пов'язане з Issue через `Closes #N`.

### 18. Що потрібно вказати у розділі про академічну доброчесність?

Назву використаного ШІ-інструмента або твердження про його невикористання, ролі, запити, прийняті рекомендації, виправлені помилки та підтвердження розуміння поданого коду.

### 19. Яку роботу виконує агент DevOps, а яку — Валідатор?

DevOps допомагає з інфраструктурою: Maven, аналізатором, JAR і CI. Валідатор складає крайові випадки, перевіряє результати та формулює дефекти.

### 20. Який рядок програми найскладніше пояснити і чому?

Найскладнішим є фрагмент із обробкою одного CSV-рядка, де послідовно виконуються перевірка кількості полів, перевірка тексту, перетворення чисел, перевірка від'ємних значень і включення запису в статистику. Він містить кілька залежних етапів і виняток `NumberFormatException`.
